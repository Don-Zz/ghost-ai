- `canvas-dnd-shape-fixes.md` — Fixed drag-and-drop and shape rendering (2026-05-06):
  - **Drag-and-drop**: Moved `onDragOver`/`onDrop` from the outer wrapper `div` back onto the `<ReactFlow>` component in `canvas.tsx`. The React Flow API expects these handlers on the `<ReactFlow>` element — the library routes drop events through its own container, and `screenToFlowPosition` is only reliable when the event originates from there. The outer-div placement was bypassing this contract and silently dropped the events.
  - **Shape rendering**: Added `.react-flow__node-canvasNode` CSS override in `globals.css` (padding: 0, border: none, border-radius: 0, background: transparent, overflow: visible). React Flow's default stylesheet applies `border: 1px solid #1a192b`, `border-radius: 3px`, and `padding: 10px` to every `.react-flow__node`, and our global `* { border-color }` injected the project colour on top. This was wrapping every custom node in a padded rounded box, making rectangle, pill, and circle shapes visually identical. Stripping those defaults lets each `ShapeComponent` own its own geometry.

- Dark-only theme enforced via CSS custom properties in `globals.css`, mapped to Tailwind v4 utilities via `@theme inline`. No light mode variables or `.dark` class overrides — all values set on `:root`.
- shadcn `--background`, `--foreground`, etc. variables are mapped directly to the project's hex design tokens so shadcn components inherit the correct dark palette without any class toggling.
- `components/ui/*` files are not modified after installation; project-level styling lives in app-level components.

## Session Notes

- Project is a Next.js 16 / React 19 / Tailwind v4 app. Path alias `@/*` maps to project root.
- `globals.css` uses Tailwind v4 `@import "tailwindcss"` syntax (no `tailwind.config.js`).
- shadcn components installed under `components/ui/`. shadcn version 4.6.0.
